How Torrent Intake works and where settings are changed
  1. A submitted torrent is tagged and downloaded into the configured local or NAS staging boundary.
  2. When complete, Torrent Intake pauses it and repeats the qBittorrent ownership, tag, path, completion, and file-identity checks.
  3. Every regular file is streamed to the persistent private ClamD sidecar. Clean file checkpoints survive restarts.
  4. Clean content is promoted to its approved media destination. Infected content follows the read-only action shown above.
  5. Structured events are written durably for the central notifier; Torrent Intake does not send Telegram directly.

Host bind mounts cannot be changed from inside this container. Update the Compose or Portainer stack and recreate the application when a deployment-managed setting changes.

Compose-only values such as the image tag, host port, numeric UID/GID, host-side bind paths, and ClamD sidecar limits are not visible to the application. Inspect the deployed stack for those values.

The live scan-slot and maintenance controls are intentionally kept in the Scan Queue toolbar.
